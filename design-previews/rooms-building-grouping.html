Implementation approach (components/rooms/rooms-directory.tsx)

groupingObject.groupBy (or a reduce) over filteredRooms by room.building ?? "Unspecified", preserving first-appearance order (not alphabetical — the current fetch order is already a deliberate ground→basement→3rd...6th floor wayfinding sequence per rooms/page.tsx's own comment; alphabetical Arabic order would scramble that)
Not hardcoded to "المبنى الرئيسي" — any distinct building value gets its own section automatically, as shown in the illustrative example above.
section headerBuilding2 icon + <h2 lang="ar" dir="rtl">{building}</h2> + room count, bottom border — new markup, no existing component reused since nothing quite like it exists yet
containereach building's header + card grid now sits inside a shared rounded frame (rounded-[22px] — bigger radius than the 16px cards, so the frame reads as the bigger containing shape) with an inset shadow instead of the cards' own outward one
Background is a vertical gradient, bolder near the header and fading lighter toward the bottom edge — the same "stronger tint fading to lighter" language the room card headers already use (bg-gradient-to-br from-X/25 to-X/5), just vertical and in a neutral gray-blue instead of a category color. Page recedes, frame sits as a tray, cards float forward on top with their existing shadow-sm. 20px padding keeps cards off the frame edges.
container fadethe frame's tint/border/inset-shadow moved onto a separate absolutely-positioned .building-frame-bg layer behind the header/cards, masked with mask-image: linear-gradient(to bottom, black 0%, black 50%, transparent 92%) (+ -webkit-mask-image)
mask-image on an element masks everything it renders, content included — masking .building-frame directly would have faded the second row of cards along with the background, which breaks "keep the cards unchanged." Splitting the decoration onto its own layer behind the real content (z-index: 0 vs. z-index: 1) lets the frame dissolve — no border, corner, or tint below the fade line — while the cards stay fully opaque regardless of where they sit vertically.
card location lineformatRoomLocation(room.building, room.floor) → just formatRoomField(room.floor)
Building is now implied by the section; repeating it per card was the actual redundancy being fixed.
search/amenity filteringunaffected — still filters the flat room list first, then groups the filtered result, so a search that matches rooms across 2 buildings still shows 2 sections (each only with its matching rooms)
a room with no building setfalls into its own "Unspecified" section (rather than crashing or being silently dropped) — doesn't apply to any of the 6 real rooms today, all of which have building set
gridsame grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4 per building section — the per-card grid itself doesn't change, it's just repeated once per building group instead of once globally
